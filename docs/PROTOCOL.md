# 协议与实现边界

基于用户自己安装的客户端进行静态分析，并以实际 NAS 请求核对。实现针对当前观察到的 UGOS Pro 客户端接口，厂商升级可能改变协议。

## 三种请求方式

1. 普通 NAS 文件管理：会话决定 token 位于 URL 或请求头。HTTPS 请求加入原 token 的 MD5 认证标记；请求头 token 使用登录返回的服务器公钥进行 RSA PKCS#1 v1.5 加密。保留正常系统 TLS 校验。
2. 同步引擎代理：从 NAS 的 apiKey 接口取得引擎 key，独立代理请求使用 `X-API-Key`，并在 URL 及必要的请求头携带原会话 token。这个代理不经过普通文件接口的 RSA 转换。
3. 同步 WebSocket：独立连接 NAS，使用对应的 token／UGK 认证，发送本地引擎身份及 `cli_hb`，每 8 秒保活。断线后按 5、15、30 秒退避重连。

登录的设备 UUID 与客户端连接标识是不同字段。密码加密使用登录挑战公钥；后续请求加密公钥来自登录响应，不能混用。

## 目录与映射

实际调用 NAS 文件管理的个人目录、共享目录和子目录接口。目录选择不使用演示数据。选择完成后检查写入权限。

两端配置同一目录 ID，保留已有配置字段，添加必要对端身份。上传配置为本地 sendonly／NAS receiveonly；下载反向；双向为两端 sendreceive。使用文件监视和周期重扫。

创建请求失败时先回读配置。如果请求已提交，就保留映射；无法确认结果时给出 ID，避免盲目回滚。撤销只处理本次新生成的映射。部分 NAS 不支持带目录 ID 的细分配置路由，使用其完整配置接口时先读取最新配置并保留其他条目。

## 进程与私有配置

引擎由单独监督程序持有。端口已监听时不启动另一份配置实例；只使用已验证签名与摘要的本机引擎。控制 API 只监听回环地址。用户关闭状态面板后后台服务继续运行。

仓库及构建产物仅包含自己编写的应用。厂商引擎、私有运行参数、证书与数据库留在本机，均不进入 Git。
